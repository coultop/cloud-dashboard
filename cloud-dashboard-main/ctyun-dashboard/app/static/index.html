为什么必须抓一次，不能直接输短信验证码？
  • 中国移动 App 的每个请求都带 xs / x-sign / x-token 三个签名头，由 App 内的原生算法用本机生成的 xk 与毫秒时间戳算出来，手机号还要再做一次 RSA 加密。面板没有这套算法，发不出「看起来像 App」的登录请求 —— 复刻它等于把 App 的登录协议重写一遍，且随版本失效。
  • 网页版短信登录已经走不通：实测 login.10086.cn/loadToken.action 返回 rspCode 3001，wx.10086.cn 全站挂维护公告。
  • autoLogin 是官方自己的免密自动登录：请求体里就带着长效凭证，重放一次就能换到会话 Cookie。所以抓一次 = 长期可用，之后不用手机、不用验证码。
🍎 iPhone / iPad · Stream（免费）
  1. App Store 装 Stream（Surge / Loon / Quantumult X 也可以）。
  2. Stream 里点「HTTPS 抓包」→ 装描述文件：设置 → 通用 → VPN 与设备管理 → 安装；再到 设置 → 通用 → 关于本机 → 证书信任设置 → 打开 Stream 的开关。
  3. Stream 点「开始抓包」，从后台彻底划掉「中国移动」，再打开 App（必须冷启动，热启动不发 autoLogin）。
  4. Stream 里搜 autoLogin，点开这条 → 复制 Request Body / 请求体（一长串 base64；已解密成 JSON 也行）。
  5. 停止抓包（抓完就关 HTTPS 解密）。
🤖 Android · Reqable（或 HttpCanary）
  1. 装 Reqable（或 HttpCanary），进「设置 → 证书」导出 CA 证书。
  2. 设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书 → 选刚才导出的文件。
  3. Reqable 开始抓包 → 冷启动「中国移动」→ 过滤 autoLogin → 复制请求体。
  4. Android 7+ 只认系统证书的 App 可能抓不到；抓不到就用下面的电脑方案。
💻 电脑 · mitmproxy / Charles（手机同 WiFi 走代理）
  1. 电脑装 mitmproxy（终端跑 mitmweb，默认 8080）或 Charles（8888），开 HTTPS 解密，MitM 域名填 client.app.coc.10086.cn。
  2. 手机 WiFi 设手动代理：电脑 IP + 端口。
  3. 手机浏览器打开 http://mitm.it（Charles 用 chls.pro/ssl）装证书并信任（iOS 还要去「证书信任设置」打开）。
  4. 冷启动中国移动 App → 在电脑上过滤 autoLogin → 复制 Request Body。
常见坑：① 复制成「响应体」→ 面板会提示「这不是 autoLogin 的请求体」；② 只复制了一部分（base64 很长，别手抖截断）；③ 没有冷启动 App，抓不到 autoLogin；④ 证书没信任，手机里只剩 CONNECT 隧道看不到内容；⑤ 抓到的是网页版 wap 而不是 App 的请求。
只读：只查询话费、消费、流量、积分，不签到、不办理、不修改账号数据。

🚀 版本更新说明 (v2.3.1)

✨ v2.3 移动公众全量融合 · 移动爱家 SCG 底座打通与开机能力恢复 · 自动开机守护默认开启 (最新)
发布时间：2026-09-28
  • 📡 移动公众（中国移动云电脑 · 公众版）全量融合，三平台同台管理：新增独立登录通道（账号密码）与分层保活 —— L1 账号态探针 + L2 桌面登记，配套官方协议侧车；提供云电脑开机 / 关机 / 重启能力；新增静默会话信号（updateSessionStatus + pushConnectEventData，默认执行、界面与日志均不显示）与 accessToken 25 分钟主动续期（平台 TTL 约 30 分钟，消除周期性 401）。开关机状态改用合成判定（探测证据 > 平台操作能力表 > 平台状态字段），平台字段滞后或失真时界面不再跟着错。
    ⚠️ 依赖说明：移动公众协议侧车需 Python 3（Docker 镜像已内置 python3 + requests + pycryptodome；本机直跑需自备）。天翼云与移动爱家仍为零 Python 依赖。
  • 🖥️ 移动爱家「深信服 SCG」底座打通（含开机能力恢复）：定位到 SCG「零应答」根因是缺少官方 CEM 控制面（firm-auth 的 scAuthCode 只是 OAuth 扩展授权令牌，必须经 CEM 换取会话材料）。现已实现 CEM 官方链路（OAuth 扩展授权 → getConnectInfo 触发开机 → getVmReadyStatus 就绪轮询），并打通 SCG 保活数据面（同 socket TLS 升级 + trunk/SPICE），真机验证：鉴权通过、会话建立并收到首帧 SPICE 数据。「名下云主机」恢复『开机』与『🛡️守护』控件。
    ⚠️ 开机全程走账号自有凭据的官方通道：ZTE 走 CAG HTTPS（RSA 公钥动态获取 + 保留 TLS 证书校验），SCG 走 CEM 官方接口；不伪造客户端身份、不关闭证书校验。保活有效性仍按诚实口径标注（未被证明有效），以真机长期观察为准。
  • 🛡️ 「自动开机守护」默认开启（移动公众 + 移动爱家 SCG）：账号级 + 单机双开关、同机 10 分钟冷却、只对「确定关机」下发（绝不盲开）、时长耗尽熔断。移动公众一刀切默认开；移动爱家按底座分叉 —— 含 SCG 的账号默认开（CEM 通道，无额外代价），纯 ZTE 账号保持默认关（ZTE 开机走 CAG 会真实消耗限时套餐时长，需显式开启）。开关默认口径由单一判定入口驱动，界面与后端同源不漂移。
    ⚠️ 如实说明：平台约 48 小时强制关机无法被 HTTP 层保活阻止，守护的职责是关机后自动恢复。
  • 🔑 30 天免登录：登录新增「30 天内免登录」勾选（默认勾选）。勾选后无论容器重启还是关闭页面都保持登录，只有点「退出」才吊销；服务端仅持久化勾选会话（原子写、权限 0600），未勾选绝不落盘，登出即吊销、重启不复活。

✨ v2.2.5 挂机中断鉴别观察窗延长至 5 分钟
发布时间：2026-09-23
  • 🔍 挂机中断鉴别的观察窗由 90 秒延长至 5 分钟：当挂机长连接被断开时，系统需要判断"是不是有真人在使用云电脑"。原实现只观察 90 秒，实测该窗口内官方挂机计时可能尚未落账变化，导致误判为"无人在用"而重新认领，从而把正在使用的用户顶下线。
    现改为 5 次采样 × 60 秒 = 总计 5 分钟：
    · 采样间隔保留 60 秒，以覆盖官方"按分钟粒度落账"的跳变边界（若只睡 5 分钟取一次，可能落在两次跳变之间而看不到增量）；
    · 每轮采样都会记录日志（🔎 鉴别采样 N/5），可据此判断官方计时究竟需要多久才会变化；
    · 判定阈值仍为 30 秒增量：计时增长 → 判定有真人在用，立即让位避让；计时冻结 → 判定无人在用，允许重连续挂。
  • 📊 便于定位根因的采样日志：新增逐分钟采样日志，可直观看出"官方计时在 5 分钟内是否变化、第几分钟开始变化"，为后续是否需要进一步调整判定策略提供实测依据。
  • ⚠️ 已知局限（如实说明）：本调整只在"官方计时属于延迟落账"时有效。若 5 分钟内计时仍恒定不变，则说明该计时不随本系统的协议会话推进（可能按官方客户端会话结算），此时延长窗口无效，需要改为"取不到计时增长证据时，一律按可能有真人处理（不重连）"。此判断需以实际日志为准。
